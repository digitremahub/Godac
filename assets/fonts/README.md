`NotoSans-Regular.ttf` — Google Noto Sans, SIL Open Font License 1.1 (https://openfontlicense.org/open-font-license-official-text/).
Vendored from `node_modules/next/dist/compiled/@vercel/og/noto-sans-v27-latin-regular.ttf` (Next.js bundles it for `next/og`) rather than fetched separately — same font, already present in this project's dependency tree.

Used by `lib/payslips/generate-pdf.tsx` and `lib/ticpe/generate-pdf.tsx` instead of relying on `@react-pdf/renderer`'s pdfkit-provided standard fonts: pdfkit lazily `require()`s those from `node_modules/pdfkit/js/standard-fonts/*` using a dynamically-built path at render time, which Next's output file tracing cannot follow — `next.config.mjs`'s `outputFileTracingIncludes` cannot force node_modules paths into the Vercel serverless bundle either (confirmed by testing: an explicit, non-glob node_modules path was still silently dropped), so every PDF generation crashed in production with `Cannot find module '.../pdfkit/js/standard-fonts/Helvetica.cjs'`. A font file embedded directly under the project root (this directory) traces correctly, the same way `content/help/**` already does for `lib/assistant/help-content.ts`.
